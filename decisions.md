# decisions

- 2026-10-12: Created a local virtual environment `reachy_test` (venv) in the project folder, based on the Anaconda Python 3.14.6 (`C:\Users\lbsupan\AppData\Local\anaconda3\python.exe`). Packages are tracked in `requirements.txt`.
- 2026-10-12: Added the project dependencies to `requirements.txt` (no versions pinned yet): `reachy-mini`, `openai`, `openai-whisper`, `sounddevice`, `numpy`, `scipy`.
- 2026-10-12: Installed `requirements.txt` into `reachy_test` on Python 3.14 without problems (e.g. reachy-mini 1.11.0, openai 3.29.0, openai-whisper 20250625, torch 2.14.1+cpu, numpy 2.5.4, scipy 1.18.1).
- 2026-10-12: Added `opencv-python` and `ultralytics` to `requirements.txt` for computer vision / object detection and installed them (opencv-python 5.0.0.93, ultralytics 8.4.175, plus torchvision 0.29.1 as a dependency).
- 2026-10-12: The `reachy-mini-daemon.exe` launcher in `reachy_test\Scripts` is blocked by system policy (access denied). Added `run_sim_daemon.py`, which starts the daemon from Python in MuJoCo sim mode: `reachy_test\Scripts\python.exe run_sim_daemon.py`.
- 2026-10-12: The GStreamer wheel used by `reachy_mini` puts its own `libexpat.dll` on the DLL search path. That DLL conflicts with Anaconda's and makes `pyexpat` fail to load (`DLL load failed while importing pyexpat`). Workaround: `import pyexpat` before `reachy_mini` (done in `run_sim_daemon.py` and `llmtest.py`).
- 2026-10-12: Fixed `llmtest.py`, which used `np` without importing it (added `import numpy as np`). Ran it against the local Ollama `phi4-mini` model and the sim daemon, and it worked.
- 2026-10-12: In `visiontest.py`, the head movements now run in a background thread (`head_movements`). `look_at_world`/`goto_target` block until each move finishes, so running them in the thread lets the camera and YOLO loop keep going and the movement shows up in the video. A `threading.Event` stops the thread when the user quits with 'q', and the thread is joined before the connection closes.
- 2026-10-13: `whispertest.py` crashed with `FileNotFoundError` (WinError 2). The cause was that `whisper.transcribe(<filename>)` needs the external `ffmpeg` CLI, which isn't installed. Fixed by passing the recorded float32 mono 16 kHz NumPy array straight to `transcribe()`, so no temporary WAV file (`scipy.io.wavfile`) and no ffmpeg are needed.
- 2026-10-14: Created a new venv `reachy_test_14` from the Anaconda Python 3.14.6 and installed `requirements.txt` into it (e.g. reachy-mini 1.11.0, mujoco 3.15.0, openai 3.31.0, torch 2.14.1+cpu, transformers 5.19.0, ultralytics 8.4.177). `pip check` reports no broken requirements, and all packages import. Run the project with `.\reachy_test_14\Scripts\python.exe` (see `AGENTS.md`).
- 2026-10-14: Converted `moodtest_live.py` from DeepFace to Hugging Face `transformers` (`image-classification` pipeline with `dima806/facial_emotions_image_detection`, same model as `facemood_transformer.py`). The pipeline only classifies images, so each face is first found with OpenCV YuNet (`cv2.FaceDetectorYN`). Its ONNX model `face_detection_yunet_2023mar.onnx` is downloaded from the HF Hub repo `opencv/face_detection_yunet`. Reason: OpenCV 5 no longer ships Haar cascades (`cv2.CascadeClassifier` is missing). The face crop is converted from BGR to RGB and classified. Added `huggingface_hub` to `requirements.txt` because the script imports it directly (it is already installed as a dependency of transformers).
- 2026-10-17: Added `voicechat.py`: press ENTER to record, transcribe with Whisper, ask the local LLM (Ollama/`phi4-mini`), synthesize the reply with Kokoro-82M, and play it back through the Reachy Mini speakers. Kokoro-82M's official `kokoro` pip package (and its `misaki` dependency) requires Python <3.13, which is incompatible with the project's Python 3.14 venv. Used `kokoro-onnx` instead (pure Python + onnxruntime, no torch/misaki needed, bundles its own espeak-ng binaries via `espeakng-loader` on Windows). Added `kokoro-onnx` and `soundfile` to `requirements.txt`.
- 2026-10-17: Kokoro-82M has no official German support (only English, Spanish, French, Hindi, Italian, Japanese, Brazilian Portuguese, Mandarin) — confirmed by the user, so `voicechat.py` runs entirely in English (Whisper transcription with `language="en"`, English system prompt for the LLM, Kokoro voice `af_heart` with `lang="en-us"`).
- 2026-10-17: The Kokoro-82M ONNX model weights (`kokoro-v1.0.onnx`, ~325 MB, and `voices-v1.0.bin`, ~27 MB) are downloaded manually into `tts_models/` (git-ignored) from https://github.com/thewh1teagle/kokoro-onnx/releases/tag/model-files-v1.0. Important: the newer `model-files-v1.1` release's `kokoro-v1.0.onnx` uses a different graph (`input_ids`/float `speed` input) that is incompatible with the installed `kokoro-onnx` 0.4.7 (the newest version supporting Python 3.14), which raises `onnxruntime.capi.onnxruntime_pybind11_state.InvalidArgument` about the `speed` input dtype. The `model-files-v1.0` release's `kokoro-v1.0.onnx` (older `tokens`/float32-speed export) works correctly with `kokoro-onnx` 0.4.7.
- 2026-10-20: Added `llmtest_2.py`, eine Variante von `llmtest.py`, die den ReachyMini-Daemon nur einmal verbindet und danach in einer Endlosschleife per `input()` auf der Konsole einen `user_voice_input` entgegennimmt, ihn an das lokale LLM schickt und die zurückgegebene Aktion ausführt. Eingabe von `exit`/`quit` beendet die Schleife.
